# 实机验收

模拟测试通过不等于真实录音、消息接收或系统睡眠通过。每次记录版本、系统、设备、操作时间、预期与实际结果。菜单“开始实机验收记录”只记录有限元数据，不录音、不自动发送、不触发睡眠。

## 额度

在 Codex 账户页面与本工具分别刷新。核对 5 小时/周窗口是否存在、剩余比例、重置时间、昨日/累积 Token。不同小数位按相同整数核对。不可用时不得显示为零。更改系统时区后，两处时间应指向同一个绝对重置时刻。断网后手动刷新，应显示失败及上次额度，恢复网络再刷新应恢复正常。

## 音量／亮度与屏幕同步提示（构建 13）

在实际 Touch Bar 设备上操作，先记录音量与亮度原值，完成后恢复。以下是验收步骤，不表示已经全部通过。

1. 在工具显示区域双指向左／向右滑动，核对当前输出设备音量变化；三指操作核对内置屏幕亮度变化及最低 5% 限制。
2. 核对 Touch Bar 百分比、屏幕提示百分比与实际控制值一致。屏幕提示应显示正确图标和进度，不改变当前任务页面。
3. 保持其他应用的输入框为当前焦点后调节，确认焦点与正在输入的内容不受影响；提示上的鼠标点击应穿透到原应用。
4. 松手后确认屏幕提示约 0.8 秒内消失；短时间内再次调节，确认新的提示不会被旧计时任务提前关闭。
5. 在任务和语音按钮附近以多指开始手势、调节中改变手指数，确认没有误打开任务、启动录音或触发其他按钮。
6. 分别测试手动收起、锁屏、息屏、真实系统睡眠和切换用户，确认提示立即隐藏，恢复后无残留窗口。
7. 在多显示器、不同桌面和全屏应用中操作，核对鼠标所在屏幕下方的提示位置、可见性和焦点保持。
8. 如果有不支持软件音量的输出设备，测试不可调节状态；调节期间切换音频设备，确认显示说明并要求重新滑动，不显示虚假百分比。

程序内检查可在已登录的图形桌面运行：

```sh
.build/release/CodexTouchBar --verify-control-hud /tmp/codex-control-hud-review
.build/release/CodexTouchBar --verify-control-input
```

HUD 检查注入模拟反馈并输出音量、亮度和不可调节预览，不改变系统音量或亮度。它可以验证显示、替换、隐藏、取消和焦点保持，但不能替代真实多指手势及系统恢复验收。

## 常驻与系统恢复

1. 在任务详情打开某个步骤正文，记住步骤与页码。
2. 切换 Finder、TextEdit 和 Codex，检查 Touch Bar 保持同一任务/页码。
3. 手动收起，切换应用，确认不会抢回；再主动显示。
4. 锁屏并解锁，确认关麦、恢复原页；不要把单纯息屏当作系统睡眠。
5. 保存其他工作后，通过苹果菜单睡眠或合盖进入真实睡眠，唤醒解锁后检查原页、状态和额度恢复。
6. 记录中必须分别出现 systemWillSleep / systemDidWake，且恢复后可见。合成通知只能算程序路径测试。

## 真实语音与纠错

在需要接收验收消息的任务打开语音输入，确认任务标题。实际说：

“这是一条 Touch Bar 语音验收消息，请确认收到，并继续原来的工作。”

1. 确认“已收到声音”，结束后停止录音，文字最终进入复核页。
2. 普通中文和 Codex / Touch Bar 技术词分别核对。不以合成语音文件代替真人录音。
3. 点编辑，修改错字，核对接收任务完整名称，保存；必须回到复核而不是立即发送。
4. 点击发送，在目标 Codex 任务核对只收到一条且内容与修改后相同；其他任务不能收到。
5. 再试取消、空白编辑、录音时切换任务、锁屏关麦。开始录音时固定的接收任务不得随排序改变。
6. 实际发送确认与错误不能靠 UI 自己宣称通过；以 Codex 中收到的消息及回复为依据。
